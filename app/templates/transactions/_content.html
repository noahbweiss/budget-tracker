{# Transactions list — one persistent toolbar (filter + bulk actions) plus table + pagination. Rendered inside #transactions-content on a normal page load, and returned standalone (this file only) for every HTMX interaction on this page: changing the view filter, paging, or a bulk action's response. The toolbar is always fully rendered, action buttons included — it never pops in/out. The buttons start `disabled` (nothing's selected right after any render, since a swap always clears the row checkboxes that were there before) and js/transactions.js enables/disables them as row checkboxes are checked/unchecked, rather than toggling the whole bar's visibility. Being part of this fragment (not a separate region outside it, as an earlier version had it) is what makes the toolbar automatically "just there" with no separate sync mechanism needed — the hidden current_view/current_page inputs the buttons' hx-include reads are right here too, always current.
